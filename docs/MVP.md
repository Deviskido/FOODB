# FOODB MVP 사용 안내

기준일: 2026-11-18

## MVP의 범위

수동으로 입고한 원료를 측정·판정하고, 사람이 승인한 **단일 원료 고정 레시피**로 생산하여 실제 수율과 재고 이력을 남깁니다. 자동 조정·라이선스·배송·장비 연동은 확장 개발로 분리했습니다.

최소 앱은 Node 26과 내장 SQLite로 동작합니다. React/Bun 화면과 같은 도메인 API를 사용하되, 브라우저 화면은 패키지 없이 제공되는 HTML/CSS/JavaScript입니다.

## 설치 없이 실행

Node 26.x가 설치된 사용자 터미널에서:

```sh
cd /Users/dylankang/Downloads/testomo/FOODB
npm run doctor
npm run verify:mvp
npm run start:mvp
```

**http://127.0.0.1:3000**을 엽니다. 첫 화면에서 조직·소유자를 만들고 로그인합니다. 비밀번호는 최소 12자이며 기본 계정은 없습니다. 최초 계정은 모든 운영 역할을 가집니다.

`npm install`이나 `bun install`, 프런트엔드 컴파일은 필요하지 않습니다. Node 26.5.0에서 전체 테스트 32개와 JavaScript 문법 검사를 통과했습니다.

단, 이 개발 세션은 포트 바인딩을 `EPERM`으로 거부했고 Chrome 실행도 실패했습니다. 사용자 환경에서 실제 서버·브라우저 동작을 확인해야 합니다.

## 운영 순서

1. **보관 정책 승인**: 데이터 보관 목적과 기간을 입력합니다. 운영 데이터 입력 전 필요한 초기 단계입니다.
2. **입고**: 로트명·원료 종류·kg 중량을 입력합니다. 원료 종류는 예를 들어 `tomato`처럼 일관된 식별값을 사용합니다. 내부 저장 단위는 정수 mg입니다.
3. **측정**: 원료 로트, °Bx 또는 pH, 단위, 측정값과 불확실성 하한·상한, 방법, 시각을 기록합니다. 서로 다른 항목의 단위를 혼용하면 서버가 거부합니다.
4. **기준 작성·승인**: 사용 용도·허용 범위·측정 유효시간을 설정하고 승인 근거를 기록합니다. 임의의 기본 기준을 자동 승인하지 않습니다.
5. **판정**: 승인된 기준으로 로트를 판정합니다. 적합·부적합·검토 필요 결과를 모두 저장합니다. 마지막 판정은 재고 표에 표시됩니다.
6. **고정 레시피 작성·승인**: 단일 원료 종류, 투입 중량, 예상 수율, 단계별 작업 지시, 알레르기와 검증 범위를 입력하고 승인합니다. 예상 수율은 총 투입량을 초과할 수 없습니다.
7. **생산 준비**: 원료와 승인된 레시피를 선택합니다. 펼쳐 볼 수 있는 작업 지시와 투입량을 확인하고 예약합니다. 예약·승인 스냅샷·배치 생성은 한 트랜잭션입니다.
8. **생산 시작**: 준비된 배치를 선택해 시작합니다. 현재 보류·품질 증거·재고·레시피 상태를 다시 확인한 후 재고를 소비합니다.
9. **작업 기록**: 각 단계의 실제 수행 내용을 입력합니다. 지시와 다른 점이 있으면 생산을 보류합니다. chef의 검토 근거로 재개할 수 있으나 안전 보류가 있으면 재개하지 못합니다.
10. **생산 완료**: 모든 단계를 기록한 후 실제 완제품 kg 중량을 입력합니다. 완제품 로트·공정 손실·원료 계보가 저장됩니다.

시작 전 생산은 취소해 예약을 반환할 수 있습니다. 시작 후에는 소비된 재고를 취소 버튼으로 되돌리지 않습니다. 상태 충돌 오류가 나면 헤더의 **새로고침**으로 최신 기록을 확인하세요.

## 권한

- `quality` 또는 `robotics`: 입고.
- `quality`: 측정·품질 기준·판정.
- `chef`: 레시피 작성·승인, 생산 차이 검토.
- `chef`와 `kitchen` 모두: MVP의 통합 생산 준비.
- `kitchen`: 생산 시작·단계 기록·완료.
- 모든 구성원: 안전 우려 신고.
- `safety`: 안전 보류 해제.
- `owner`: 계정 추가·보관 정책·운영 내보내기.

작업자 추가 시 역할은 쉼표로 구분합니다. 예: `chef,kitchen`. 조회자에게는 비공개 레시피와 생산 지시를 제공하지 않습니다. 다단계 역할 분리 운영은 React/Bun 확장판의 Adaptations/Production 화면을 이용할 수 있습니다.

## 데이터와 데모

| 실행 | 포트 | 기본 데이터 폴더 |
| --- | --- | --- |
| `npm run start:mvp` | 3000 | `mvp-data` |
| `npm run demo:mvp` | 3001 | `mvp-demo-data` |
| `bun run start` — 확장판 | 3000 | `data` |

데모는 시뮬레이션으로 표시되는 빈 작업공간입니다. 시험 계정과 기준을 직접 만드세요. 같은 폴더를 운영·시뮬레이션에 번갈아 사용하면 시작이 거부됩니다. 기본 폴더와 데이터 파일은 Git에서 제외합니다.

정상 종료는 Ctrl+C입니다. 포트 시작에 실패해도 프로세스 잠금 파일을 제거하도록 구현했고, 실패 경로를 검사했습니다. 비정상 종료로 `server.lock`이 남으면 실제 프로세스가 종료됐는지 확인한 뒤 처리하세요.

## 백업·복원

서버를 정상 종료한 뒤 새 목적지에 백업합니다.

```sh
npm run backup:mvp -- ./mvp-data ./snapshots/mvp-backup
npm run restore:mvp -- ./snapshots/mvp-backup ./restored-data ./mvp-data/control/deletions.json
```

복원에는 최신 삭제 지시 파일이 필요합니다. 기존 폴더를 덮어쓰지 않으며, 세션·장비 자격 증명을 무효화하고 복원 보류를 설정합니다. `APP_DATA_DIR=./restored-data npm run start:mvp`로 시작해 소유자로 로그인하고, 재고·증빙·보류를 확인한 후 화면의 복원 확인 양식을 제출합니다. Windows의 환경 변수 설정 방법은 셸에 따라 다릅니다.
